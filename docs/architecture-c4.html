DC-Designer アーキテクチャ（C4 モデル）

はじめに

ひとことで言うと

  • ポスターやスライドを AI に作らせ、編集・発表・書き出しまでできるアプリ。
  • ブラウザの画面と、手元で動く API サーバーの 2 つでできている。
  • AI は ChatGPT のサインインで使い、保存はすべて PC のファイル。
  • 推定画像生成の既定（Codex）は ChatGPT プランの枠を使う。

記号の見方

  • 人システムを使う人や役割
  • システム説明の対象になっているシステム全体
  • 外部システム対象の外にあって、つながっているシステム（自分たちでは作っていないもの）
  • コンテナ単独で動くアプリやデータの置き場所（Web アプリ、API サーバー、DB、ファイル置き場など）。Docker のコンテナとは別
  • 外部コンテナ対象の外にあって、つながっているコンテナ（自分たちでは作っていないもの）
  • コンポーネント1 つのアプリの中で、役割ごとにまとまったコードのかたまり
  • ──▶矢印。頼む側から頼まれる側へ向く。上の文字が「何をするか」、下の文字が「通信の方式」
  • 破線の枠その中の要素がどのシステム・アプリに属するか
  • ● ●流れる点。橙は頼む向き、緑は返事（矢印と逆向き）

書いてあることの確かさ

  • 事実コードや資料で確かめたこと
  • 推定状況から考えたが、確かめきれていないこと
  • 未確認わからなかったこと。判断に使う前に確かめる
  • 将来案まだ無い、これからの案

前提・気をつけること

未確認まだ確かめていない

  • 画像生成 API の応答形式は、コードから読んだだけで実行していない。

推定推定していること

  • Codex CLI は ChatGPT プランの枠を消費する（README の記述より）。

将来案これからの案

  • ネット公開（SaaS）は、AI の費用とサインインの申請が未解決で保留中。

事実前提（確かめた事実）

  • すべて 1 台の PC（WSL を含む）で動く。デプロイ設定や CI は無い。
  • API サーバーは自分の PC からの通信だけを受け付ける。
  • データベースは使わない。保存はすべてローカルのファイル。
  • デザインの形式の定義は、画面と API サーバーで共有している。
  • 小さな補助部品（差分の適用・エラー変換）は C3 の図から省いた。

この図で答えることだれが使い、外のどんな仕組みとつながっている？

DC-Designer を 1 つの箱として、使う人と依存する外部システム。内部のモジュールは描かない。

この図でわかること

  • AI の推論は ChatGPT のサインインで使い、API キーは要らない
  • 画像生成は 4 つの方法から設定で選ぶ
  • 自前のサーバーやデータベースは無く、PC 1 台で完結する

人システム外部システム破線の枠＝どこに属するか矢印＝頼む側 → 頼まれる側点: ● 頼む ● 返事

ChatGPT にサインインする

初回はクライアント登録をし、以後は保存した ID を使う

  1. ブラウザ（利用者） → Web アプリ（SPA）：サインインを押す
  2. Web アプリ（SPA） → ルーター：ログインを始めるHTTP（新しいタブ・Vite 経由）
    新しいタブで開く
  3. ルーター → ChatGPT サインイン：認可を準備関数呼び出し
    照合用の値を覚えておく
    根拠: server/chatgpt-auth.ts:190
  4. ChatGPT サインイン → ルーター：サインイン先を返す関数呼び出し
  5. ルーター → Web アプリ（SPA）：OpenAI の画面へ移すHTTP（新しいタブ・Vite 経由）
  6. ブラウザ（利用者） → OpenAI（auth.openai.com）：認可画面でサインイン・同意HTTPS
  7. OpenAI（auth.openai.com） → ブラウザ（利用者）：戻り先へ移すHTTPS
  8. ブラウザ（利用者） → ルーター：認可コードを返すHTTP 127.0.0.1（直接）
  9. ルーター → ChatGPT サインイン：認可を完了関数呼び出し
    照合用の値（state）を確かめる
  10. ChatGPT サインイン → OpenAI（auth.openai.com）：トークンに交換・鍵を取得HTTPS
    ID トークンを鍵で検証する
    根拠: server/chatgpt-auth.ts:121
  11. OpenAI（auth.openai.com） → ChatGPT サインイン：トークンを受け取るHTTPS
  12. ChatGPT サインイン → 資格情報：トークンを保存ファイル
  13. ChatGPT サインイン → ルーター：戻り先を返す関数呼び出し
  14. ルーター → ブラウザ（利用者）：アプリへ戻すHTTP 127.0.0.1（直接）
  15. ブラウザ（利用者） → Web アプリ（SPA）：結果を元のタブへ渡す
    元のタブへ送り、自分は閉じる
