# エディタの App.tsx を、役割ごとのフック・関数に分ける（2026-11-02）

決定者：ユーザー（リファクタリングの依頼）

## なぜ

`src/editor/App.tsx` が 1725 行あり、次に大きいファイル（`Inspector.tsx`、814 行）の倍を超えていた。
パネルの開閉・AI の選択・レイヤー操作・アニメーション・A4 の書き出しが 1 つの関数に並び、どこを直せばよいかを探すのに時間がかかっていた。

## 何を変えたか

挙動・画面の文言は変えず、まとまりごとに外へ出した（App.tsx は 1520 行になった）。

| 新しいファイル | 中身 |
| --- | --- |
| `src/editor/usePanelLayout.ts` | 左右パネル・スライド一覧・台本欄の開閉と大きさ（localStorage のキーも移した） |
| `src/editor/useProviders.ts` | `/api/status` の読み込み、使う AI・画像生成・モデルの選択と切り替え |
| `src/editor/layerOps.ts` | レイヤーの並べ替え・削除・複製・移動・選択・追加・整列（`createLayerOps`。フックを含まないので普通の関数） |
| `src/editor/useAnimationOps.ts` | アニメーション・画面切り替え・BGM の編集と、キャンバスでの試し再生 |
| `src/editor/useA4Export.ts` | ポスターの A4 での PNG・PDF・印刷プレビューの書き出しと、用紙を A4 にそろえる操作 |

- `spec` は今までどおり App が `useHistory` で持ち、各フック・関数は `setSpec` を受け取って書き換えるだけにした。
- PNG と PDF の書き出しで同じだった「A4 の大きさかを知らせる」処理を `useA4Export` の中で 1 つにした（知らせる文言は同じ）。
- 切り出しで使われなくなった import を消した。ついでに、元から使われていなかった import（`PosterSpecSchema`・`readDataUrl`）も消した。

## 確かめたこと

- `npm run typecheck`、`npm test`（70 ファイル・704 件）、`npm run build` が通る。
- 別ポート・別の `DATA_DIR` で立てたエディタをヘッドレスの Chromium で開き、左右パネルを閉じる・開く（localStorage に保存される）、
  「文字」でレイヤーが増える、スライドのデッキで台本欄・スライド一覧・画面切り替え・BGM の欄が出ることを見た。
- コンソールの `404` と `flushSync was called from inside a lifecycle method` は、変更前の main でも同じ画面で出ている（今回の変更とは関係ない）。

## 採らなかったもの

- チャットの送信・スラッシュコマンド・台本を書く処理（`sendChat`・`runSlash`・`writeNotesTurn`）の切り出し：
  選択・履歴・デッキ・AI の進み具合など多くの状態に絡んでいて、テストで拾えない形で壊しやすいので、今回は手を付けない。
- `src/theme.ts` の独自の `readPref` を `storage.ts` のものにそろえること：今回の範囲外。
