# よく使うデザインをテンプレートとして保存し、新しく作るときに選べるようにする（2026-11-02）

決定者：ユーザー（[#58](https://github.com/itiwoja/DC-Designer/issues/58)）

## なぜ

毎回同じ配色・配置のポスターやスライドを作る人が、白紙か既存の成果物の複製からしか始められなかった。
複製は元の成果物の名前や中身を消して回る手間があり、「型」と「作ったもの」が成果物の一覧で混ざる。

## 何を変えたか

- テンプレートの単位は、**ポスターは 1 枚、スライドはデッキ丸ごと**（ユーザー確認済み）。
- 保存先は成果物と別の `data/templates/<id>.json`。形は `{ id, name, mode: "poster" | "slides", createdAt, updatedAt, specs }`。
  成果物の一覧・件数・「最近の〜」には混ぜない。
- API（`server/routes/library.ts`）：
  `GET /api/templates`・`POST /api/templates`（`{ posterId }` か `{ deckId }`、`name` は省略可）・
  `PUT /api/templates/:id`（名前の変更）・`DELETE /api/templates/:id`・`POST /api/templates/:id/use`（テンプレートから新しく作る）。
  Windows 版から呼べるよう `desktop/operations.ts` の一覧にも `templates.*` を足した。
- 保存する場所：
  - 成果物画面：ポスター・プレゼンテーションの「複製」の隣の「テンプレートに保存」。
  - エディタ：左上のメニューの「テンプレートとして保存」。未保存の編集をサーバーへ確定してから作る（確定できなければ作らない）。
  - 名前は元のタイトル・デッキ名で保存し、ホームのテンプレートの「名前変更」で変える（文字を入力するダイアログが今は無いため）。
- 使う場所：モード別のホームの見出しのすぐ下を「新しく作る」の帯にし、白紙（A4 でスタート／0 から作る）とテンプレートを横に並べた（Canva のホームを参考に。並びきらなければ横にスクロール）。
  PDF・PowerPoint を開くカードは帯の下に分けた。テンプレートのカードには「テンプレート」の札と「＋ このデザインで作る」を付け、「最近の〜」と見分けられるようにした。選ぶと新しいポスター／デッキができてエディタで開く。
  テンプレートは残る。ホームから名前の変更と削除もできる。
- 画像の掃除：テンプレートだけが使う `/generated/` の画像も「使用中」として扱い、未使用の画像の削除で消えないようにした
  （`usedBy` にテンプレートの id が入る。成果物画面の画像タブでは「テンプレート「名前」」と表示）。

## 確かめたこと

- `npm run typecheck`、`npm test`（72 ファイル・721 件）、`npm run build` が通る。テンプレートのテストは `tests/library.test.ts`、操作一覧は `tests/templateOps.test.ts`。
- 別ポート・別の `DATA_DIR` で立てた画面をヘッドレスの Chromium で開き、成果物画面とエディタのメニューから保存できること、
  ホームに出たテンプレートの名前を変えられること、スライドのテンプレートを選ぶと 2 枚のデッキがエディタで開くことを見た。

## 既知の制限

- テンプレートの中身を後から編集する画面は無い。変えたいときは、テンプレートから作って直し、もう一度保存して古いほうを消す。
- テンプレートは画像ファイルを複製せず、同じ `/generated/` のファイルを参照する。
- テンプレートの保存先には、古い形の spec を読むときに直す処理（ポスターの `upgradePoster` に当たるもの）が無い。spec の形を変えるときは、テンプレートにも同じ直しを足す。
