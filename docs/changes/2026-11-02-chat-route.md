# チャットの振り分けを関数にしてテストを付け、AI の修正結果の当て方を分ける（2026-11-02）

決定者：ユーザー（`sendChat` まわりのリファクタリングの依頼）

## なぜ

[App.tsx を分けたとき](./2026-11-02-app-hooks.md)に手を付けなかった `sendChat` は、次の 3 つが 1 つの関数に重なっていた。

- 送った文を、どの処理で受けるかの判定（/ コマンド・ページ番号の振り直し・台本・スライドの追加・全スライドへの修正・ふつうの修正）
- AI の修正（`api.edit`）の結果を、デッキ・ポスターに当てる手続き
- チャットの 1 往復の骨組み（`chatTurn`）

判定の順番に意味があるのに、テストは個々の言い回しの判定（`isRenumberRequest` など）にしかなく、組み合わせたときにどれが勝つかはどこにも書かれていなかった。

## 何を変えたか

挙動と文言は変えていない。

- 振り分けを `routeChatRequest`（`src/editor/chatRoute.ts`）という純粋関数にした。当てはめる順番は元の if の順のまま。
  `sendChat` は、その結果で処理を選ぶだけになった。
- `tests/chatRoute.test.ts` を足した。それぞれの振り分け先、ポスターではスライド向けの振り分けをしないこと、
  開いているスライドが分からないときの扱い、順番（「全スライドの台本を書いて」は全スライドへの修正ではなく台本、など）を固定している。
- `api.edit` の結果を当てる手続きを、App の中の `applyEditResult` に分けた。
  別ファイルにしなかったのは、使う関数（`openSlide`・`updateSlide`・`deleteSlides` など）を返す `useDeck` がチャットの処理より後で呼ばれていて、
  引数として渡せない（宣言より前に使うことになる）ため。
- AI が変えたレイヤーを光らせる 2 行が 3 か所にあったので、`flashLayers` にまとめた。

## 確かめたこと

- `npm run typecheck`、`npm test`（71 ファイル・714 件）、`npm run build` が通る。
- 別ポート・別の `DATA_DIR` で立てたエディタ（スライド）をヘッドレスの Chromium で開き、チャットに `/nope` を送ると
  「コマンドはありません」の通知が出て入力欄に文が残ること、`/undo` を送ると「元に戻せる AI の変更はありません」が出て入力欄が空になることを見た。

## 採らなかったもの

- `sendChat`〜`clearChat` を丸ごと 1 つのフックに移すこと：30 近い値を渡すことになり、絡み方がそのまま別ファイルへ動くだけなので。
- `chatTurn`・`undoChat`・`clearChat` のフック化：`undoChat` が `useDeck` の関数に頼っていて上と同じ理由で渡せず、残りだけでは小さすぎるので。

## 既知の制限

- AI を使う往復（ふつうの修正・スライドの追加・全スライドへの修正・台本を書く）は、サインインが要るため実際の画面では確かめていない。
  テストで固定したのは振り分けだけで、`applyEditResult` の中身は、字下げと、光らせる 2 行の `flashLayers` への置き換えのほかは、切り出し前のコードから変えていない。
