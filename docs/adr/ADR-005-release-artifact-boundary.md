# ADR-005：利用者領域に触れない隔離ビルドと許可リストでreleaseを作る

- 状態：採用（設計のみ）／ 日付：2026-10-25 ／ 決定者：AI判断（画像保護要件を具体化）
- 影響：EXE-REQ-001、002、006／EXE-FR-001、007／EXE-TBL-005
- 定義元：[同梱境界](../desktop-release-spec.md#exe-fr-001同梱境界)

## 状況

現状は画像を`public/generated/`へ保存するため、開発PCで通常ビルドするとViteのpublicコピーへ混ざり得る。`.gitignore`だけでは配布物の安全性を保証できない。

## 決定

利用者領域を持たないクリーンなWindows CIと専用ステージを使い、コードとレビュー済み資源目録にあるものだけを同梱する。署名前・署名後・最終インストーラー／asar／更新ファイルを検査し、混入・未知資源・検査不能なら公開しない。

## 代替案

| 案 | 良い点 | 不採用理由 |
| --- | --- | --- |
| 開発PCでビルドして手動確認 | 準備が少ない | 私的画像・環境変数・認証情報を持つ領域が入力になる |
| 生成フォルダの除外だけ | 設定が少ない | 別保存先・リンク・将来の追加資源・アーカイブ内部を取りこぼす |
| 許可リストと最終検査 | 由来を追え、未知資源で停止できる | 採用。資源目録と検証の維持が必要 |

## 影響

- 利用者ファイルを削除して安全化する方式は採らない。フォントの利用者キャッシュもビルド入力にしない。
- 本人承認・コード署名は別の必須条件であり、混入検査失敗を上書きしない。実装・検証前に安全性の達成を宣言しない。
