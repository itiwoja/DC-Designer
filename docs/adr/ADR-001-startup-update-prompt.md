# ADR-001：更新のダウンロードと適用を利用者の操作で分ける

- 状態：承認 ／ 日付：2026-10-25 ／ 決定者：ユーザー（選択回答）
- 影響するID：REQ-001〜REQ-004、FR-001〜FR-004、SCR-001〜SCR-003
- 定義元：[起動時の更新確認・ポップアップ設計](../desktop-update-design.md)

## 状況

exe版は起動のたびに更新を確認し、アプリ内で案内する。旧方針は通知時期が「起動時など」で、終了時の適用も許容していた。
利用者の作業中断と、意図しないダウンロード・適用を避ける必要がある。

## 決定

起動ごとに非同期確認し、新版があれば案内する。「更新する」でダウンロードし、取得・検証完了後に「保存して再起動」で適用する。
「あとで」は次回起動までの保留。通常終了・次回起動では自動適用しない。

## 代替案

| 案 | 良い点 | 悪い点・不採用理由 |
| --- | --- | --- |
| 配布ページから手動取得 | アプリの更新処理が少ない | 利用者が取得・インストールを別途操作する。アプリ内更新が選択された |
| 自動取得・終了時適用 | 操作回数が少ない | 利用者の意図しない取得・適用が起きる |
| 恒久的な版スキップ | 再通知が少ない | 起動ごとに更新を促す要望と一致しない |

## 影響

- 更新管理はmainに集約し、自動取得・自動適用を無効にする。
- 保存確認は終了イベント任せにせず、インストーラー起動前に全対象の成功を確認する。
- 配信先・署名方式の確定と実機検証は必要。今回の決定だけで配信・実装を開始したとは扱わない。
